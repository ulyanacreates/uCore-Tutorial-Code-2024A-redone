## 问答作业
1. 请列举 SV39 页表页表项的组成，结合课堂内容，描述其中的标志位有何作用／潜在作用？
    页表项总共有64位，具体的分配如下：
    * 63~54 bit: 暂时保留；物理地址的拓展位
	* 53~10 bit: 存储PPN，或者在多级页表结构，指向下一级的页表的指针
	* 9~8 bit: 预留给supervisor软件用
	* 7 bit: Dirty bit, 用与记录页是否被修改过，判断是否需要写回磁盘
	* 6 bit: Accessed bit, 用与记录页是否被访问过，由页面置换算法用到
	* 5 bit: Global bit, 记录页的映射是否全局的，判断进程切换时是否需要刷新TLB
	* 4 bit: User bit, 记录页面是否允许在U态访问
	* 3 bit: Executable bit, 记录此页映射的内容是否为可执行指令
	* 2 bit: Writable bit，记录此页映射的内容是否可写
	* 1 bit: Readable bit, 记录此页映射的内容是否可读
	* 0 bit: Valid bit, 记录此页的映射是否有效

2. 缺页相关问题
    * 请问哪些异常可能是缺页导致的？
    用户态尝试访问无效页面，用户态访问用户访问位为0的页面，尝试执行不可执行的内存内容，或者执行没有分配物理地址的指令等等
    * 发生缺页时，描述相关的重要寄存器的值（lab2中描述过的可以简单点）。
    sscratch == 发生缺页进程的 trapframe
    satp == 发生缺页的页表地址
    sepc == 完成异常处理后要返回的 PC 地址（即异常发起的指令地址）
    CPU 为 S-mode (01)。
    * 这样做有哪些好处？
    进程运行时不一定会访问其所占用的整个内存空间，那么这种策略避免了不必要的内容被分配物理内存，节省了物理内存空间。
    * 请问处理 10G 连续的内存页面，需要操作的页表实际大致占用多少内存(给出数量级即可)？
    使用SV39机制，每个物理页表项数量为512（4096/8）。叶子节点每页大小为2MiB（5124096B），10G需要5000个页面。非叶子节点每页大小为1G（2MiB512），10G需要10个页面。因此，叶子节点计算10G需要20MiB（5000*4096B）。
    * 请简单思考如何才能在现有框架基础上实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。
    我们需要建立一个表记录进程申请和已分配的内存。初次申请时不分配，只记录在表中。首次访问发生缺页时，才进行虚拟和物理地址映射，并修改进程表记录。
    * 此时页面失效如何表现在页表项(PTE)上？
    页面之前是valid，那么RWX至少有一位为1，但有效位V为0。

3. 双页表与单页表
    * 单页表情况下，如何更换页表？
    还是按如下代码这种方式进行切换， 但是这里切换的是不同进程的页表，只有在切换进程时才调用这部分代码：
    ```
    csrw satp, a1
    sfence.vma zero, zero
    ```
    * 单页表情况下，如何控制用户态无法访问内核页面？
    因为页表项有U标志，所以只需要将对应页表项的U标志置0就得到目标。
    * 单页表有何优势？
    实现更简单
    内存开销更小
    切换时不用每次切换页表并刷新TLB => 减少了切换开销，让程序效率更高
    * 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
    进程切换、U态到S态、或S态到U态时都需更换页表。因此，当执行新进程或发生异常/中断时，根据切换情况更换或保留当前页表。
